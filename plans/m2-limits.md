# M2 limits remeasurement

No `Limits::default()` value changed in atomic M2 commit 9. This file records
the local measurements used to make that decision. It does not extrapolate
from a missing run and does not claim that a component benchmark is an
end-to-end broker benchmark.

## Reproduction

Measured on frozen source commit
`fa8fe43b6ac49b4d6d176b28c370420bb8ef8751` on 2026-08-30 UTC. The durable
harness is the explicitly ignored Rust test
`real_process::measure_locked_limits_local` in
`crates/everpty/tests/resources.rs`. It uses only local Unix socket pairs,
real Linux PTYs, local child processes, `/tmp` fixtures owned by the test, and
fixed monotonic deadlines. It contains no Python harness, requires no root,
network, namespace, `tc`, or external host, and removes every child, PTY,
file, and fixture directory before returning.

Exact measurement invocation:

```sh
EVERPTY_RUN_LIMITS_MEASUREMENT=1 \
  cargo test -p everpty --features cli --test resources \
  real_process::measure_locked_limits_local -- \
  --exact --ignored --nocapture --test-threads=1
```

The final successful invocation completed at `2026-08-30T05:37:14Z` in
10.04 seconds. The test itself checks
the deterministic input and output bytes, hashes, Vim exit statuses and
unchanged `q!` fixture files. It fails rather than recording a partial result
when any 20-second socket/PTY, 15-second Vim, or bounded child-cleanup deadline
is exceeded.

The 10 MiB input is generated by the checked-in Rust `pattern_byte(index)`
function. Its length is 10,485,760 bytes and its SHA-256 is
`aa14671a80c81b4b79d506726aabcff50c95a9193542637d868d7c2a48b09415`.
The harness includes an independent SHA-256 implementation with the `abc`
known-answer assertion before it records this digest.

The throttled-reader scenario uses a nonblocking `UnixStream::pair` with the
host's default socket buffers. Each 1 ms tick permits exactly 8 KiB or 32 KiB
of reads; the producer writes until `EAGAIN`, and the test records the maximum
`written - read` backlog and `EAGAIN` count. The final harness deliberately
uses direct `read(2)`/`write(2)` on those descriptors. In this controlled
execution environment, optional `SO_SNDBUF` tuning and Rust's flagged
Unix-stream send path were rejected with `EPERM`; those failed preliminary
attempts produced no scenario results and are excluded from the tables.
Kernel-default buffering is therefore part of the recorded environment.

The cat-like scenario connects `/bin/cat` to a real raw PTY, concurrently
writes and reads the deterministic 10 MiB stream, and requires byte-for-byte
and hash equality before terminating and reaping the child process group. The
Vim scenario runs `/usr/bin/vim -u NONE -i NONE -n -N` on a real controlling
PTY. Each run performs 32 deterministic insert, movement, and redraw loops,
then `:q!`; the original file must remain unchanged.

For independent environment reproduction, these read-only commands were
recorded alongside the Cargo invocation:


The non-ignored resource regressions complement these measurements at the
broker policy boundary: a healthy writer is retained and drains byte-exactly
after real socket `EAGAIN`; a slow observer is evicted at its cap; aggregate
pressure evicts the observably most-full observer; and a later observer sees
future bytes only. Reproduce those checks with:

```sh
cargo test -p everpty --features cli --test resources -- --test-threads=1
```

## Decision for every default

| Default | Decision and evidence |
|:---|:---|
| `frame_max_body = 64 KiB` | Retain. This is a wire cap, not a throughput tuning knob. It admits one maximum input frame; the decoder plateau test proves bounded reservation for 16 incomplete frames. |
| `name_max = 64`, `error_text_max = 256`, `unix_path_max = 107` | Retain. These are pinned wire/path contract bounds. The workload supplies no evidence for changing them. |
| `startup_deadline_ms = 10,000` | Retain. Even the complete repeated Vim workload was 146–150 ms after launch and remained far inside the bound. Ten seconds preserves startup headroom on slower hosts. |
| `kill_grace_ms = 5,000` | Retain. Catchable-exit resource tests finish and reap boundedly; this slice found no evidence that warrants shortening the production TERM grace period. |
| `writer_queue_bytes = 256 KiB` | Retain. Default local Unix sockets repeatedly held 212,992 bytes before producer backpressure, while raw-PTY bursts peaked at 282,624–283,138 bytes. A separate 256 KiB broker queue is enough burst tolerance to avoid treating ordinary kernel jitter as failure while remaining hard-bounded; its test drains without loss. |
| `observer_queue_bytes = 64 KiB` | Retain. Observers are deliberately expendable under sustained lag. The local kernel already buffers 212,992 bytes; the additional 64 KiB user-space cap gives bounded slack, and the resource test proves deterministic eviction rather than PTY pause or writer loss. |
| `observer_count = 8` | Retain. It is a fan-out resource bound, not established by single-terminal throughput. Eight observers plus one 256 KiB writer queue consume at most 768 KiB before framing overhead, within the 1 MiB aggregate cap. |
| `aggregate_queue_bytes = 1 MiB` | Retain. It covers the configured writer plus all eight observer queue budgets with headroom, and the aggregate-pressure regression proves the hard ceiling and healthy-writer survival. |
| `max_connections = 16` | Retain. The explicit 17th-connection regression observes `Error(ResourceLimit)`, EOF, no slot, and no retained descriptor. The measurements offer no reason to enlarge the attack/resource surface. |
| `writer_input_queue_bytes = 64 KiB` | Retain. It admits the maximum legal 65,534-byte `Input` payload once, then applies socket backpressure without eviction; larger retention was not needed for the measured workloads. |
| `incomplete_frame_deadline_ms = 5,000` | Retain. This is an abuse bound independent of throughput. The allocation plateau and existing immutable-deadline tests cover it; the local workloads do not justify more retained partial state. |
| `accepts_per_iteration = 8` | Retain. This fairness budget is orthogonal to one-session throughput and remains below the total connection cap. No measurement indicated accept starvation. |
| `read_chunk_bytes = 16 KiB` | Retain. The same chunk size sustained 139–191 MiB/s through the exact 10 MiB PTY runs, far beyond an interactive terminal workload, without increasing per-iteration allocation. |
| `stall_deadline_ms = 20,000` | Retain. The deliberately slow 8 KiB/ms reader completed in 1,415–1,431 ms despite 1,254 producer backpressure events. Twenty seconds leaves substantial interactive scheduling headroom while the queue remains strictly bounded. |
| `pty_exit_drain_ms = 5,000` | Retain. Exact 10 MiB PTY drains completed in 52–72 ms locally. Five seconds is conservative cross-host headroom for delivering final output before detachment. |
| `control_reply_deadline_ms = 5,000` | Retain. The real-EAGAIN mock-clock regression proves retention before and closure exactly at the immutable deadline. Workload throughput does not justify altering a control-client abuse bound. |
| `list_probe_deadline_ms = 500` | Retain. This is a bounded liveness probe and was not stressed by byte throughput; no contrary local evidence was observed. |
| `metadata_max_bytes = 4,096`, `exec_label_max_bytes = 256`, `origin_label_max_bytes = 64`, `origin_count_max = 4` | Retain. These are pinned metadata/label contract caps. Stable-build fuzz targets exercise total decode/canonical encoding; workload measurements do not authorize expanding them. |

Conclusion: all named defaults remain unchanged. The repeated results show
bounded backpressure with exact bytes and ample deadline/throughput headroom;
none supplies evidence for a production behavior or dependency change.
